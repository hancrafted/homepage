## Claim 3: "45% of samples failed security tests / introduced OWASP Top Ten vulnerabilities"

**Verdict: Confirmed in substance, but the exact framing differs between Veracode's own two primary documents — flag this, don't collapse it.**

- **Blog framing — "samples," "failed security tests," "OWASP Top 10":**

  > "45% of code samples failed security tests and introduced OWASP Top 10 security vulnerabilities into the code."
  - **Locator:** Blog post, section "The Results: AI-generated Code That Works, But Isn't Safe" — first bullet under "Here are the topline stats from our evaluation:"
  - **URL:** https://www.veracode.com/blog/genai-code-security-report/
  - This is the only place across the sources checked that uses the word "**samples**." It also is the only place that names "OWASP Top 10" directly in the same sentence as the 45% figure.

- **Press-release framing — "cases" / "test cases," OWASP named in a separate sentence:**

  > "...it introduces security vulnerabilities in **45 percent of cases**."
  - **Locator:** Press release, opening/lede paragraph.

  > "In **45 percent of all test cases**, LLMs introduced vulnerabilities classified within the OWASP (Open Web Application Security Project) Top 10—the most critical web application security risks."
  - **Locator:** Press release, section "LLMs Introduce Dangerous Levels of Common Security Vulnerabilities" (second sentence of that section).
  - **URL:** https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/
  - The press release also frames it behaviorally: "when given a choice between a secure and insecure method to write code, GenAI models chose the insecure option 45 percent of the time" (same document, second paragraph).

- **Landing-page framing — "tests," no explicit OWASP mention next to the number:**
  > "AI-generated code introduced risky security flaws in 45% [of] tests."
  - **Locator:** Landing page, under the "What You Will Learn" callout, heading "Real Vulnerabilities, Real Impact."
  - **URL:** https://www.veracode.com/resources/analyst-reports/2025-genai-code-security-report/
  - This page does not pair the 45% figure with "OWASP" anywhere in its visible body text.

**Bottom line:** the 45% figure itself is consistent everywhere (blog, press release, landing page all agree on "45%"), and Veracode does explicitly tie it to the OWASP Top 10 in both the blog and the press release. But the unit being measured is described inconsistently even within Veracode's own primary sources: "samples" (blog) vs. "cases" / "test cases" (press release) vs. unlabeled "tests" (landing page) vs. "tasks" is never used for the 45% figure itself (the "80" figure is tasks; the "45%" figure is samples/cases/tests, a distinct denominator). Treat "45% of samples" as one valid verbatim rendering (from the blog) rather than the report's only or definitive framing.

## Claim 4: "Newer, larger models are no safer" (load-bearing claim)

**Verdict: Confirmed, verbatim, in both primary documents, with slightly different emphasis.**

- **Blog — direct rhetorical framing, most quotable for this exact claim:**

  > Heading: "**Aren't Newer AI Models Generating More Secure Code?**"
  > "It's a great question. Unfortunately, they don't."
  > "We evaluated LLMs of varying sizes, release dates, and training sources over a matter of years. While the models got better at writing functional or syntactically correct code, they were **no better at writing secure code**. Security performance remained **flat, regardless of model size or training sophistication**."
  > "This challenges the idea that 'smarter' AI models naturally lead to more secure outcomes. In practice, they don't."
  - **Locator:** Blog post, section headed "Aren't Newer AI Models Generating More Secure Code?"
  - **URL:** https://www.veracode.com/blog/genai-code-security-report/

- **Press release — Wessling quote, same conclusion, "larger models" framing:**

  > "'Despite the advances in AI-assisted development, it is clear security hasn't kept pace,' Wessling said. 'Our research shows models are getting better at coding accurately but are not improving at security. We also found **larger models do not perform significantly better than smaller models**, suggesting this is a systemic issue rather than an LLM scaling problem.'"
  - **Locator:** Press release, quote attributed to Jens Wessling (CTO), fourth paragraph (following the CWE/OWASP methodology paragraph).
  - **URL:** https://www.veracode.com/press-release/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/
  - Same press release, earlier Wessling quote: "Our research reveals GenAI models make the wrong choices nearly half the time, and it's not improving."

- **Landing page — condensed headline version:**
  > Heading: "**Bigger Models ≠ More Secure Code**"
  > "Larger, newer AI models didn't improve security."
  - **Locator:** Landing page, "What You Will Learn" callout, third bullet.
  - **URL:** https://www.veracode.com/resources/analyst-reports/2025-genai-code-security-report/

All three of Veracode's own sources agree on substance: model scale/recency did not improve security pass rates. The blog gives the fullest, most citable sentence ("Security performance remained flat, regardless of model size or training sophistication"); the press release attributes the same conclusion to CTO Jens Wessling by name; the landing page compresses it into a headline.

## Unverified

- **The PDF report itself:** Could not be retrieved or inspected. The download is gated behind a lead-capture form (name, business email, company, job title) on the landing page (https://www.veracode.com/resources/analyst-reports/2025-genai-code-security-report/). No direct/unauthenticated PDF URL was found via search or by inspecting the landing page's HTML, and filling out the lead-capture form with the user's personal/business information was out of scope for this research task. As a result, none of the four claims above could be checked against actual page numbers or section headings _inside the PDF_ — all locators above are to the press release, the blog post, and the landing page, which are the only openly accessible primary Veracode documents.
- **Business Wire's own copy of the press release** (https://www.businesswire.com/news/home/20250730694951/en/...): returned HTTP 403 to every fetch attempt (likely bot/TLS-fingerprint blocking), so it could not be used directly. Substance was cross-checked instead against Veracode's own identical copy hosted at veracode.com/press-release/..., which is the version quoted throughout this document.
- **Original (pre-October-2025-update) wording of the landing page:** The landing page has been edited in place since its July 30, 2025 launch (current `article:modified_time` metadata shows 2026-07-09; the page's own heading now reads "October 2025 Update: GenAI Code Security Report"). The Wayback Machine (web.archive.org) could not be fetched from this environment, so the original July 2025 wording of that specific page could not be independently confirmed — only the press release and blog post (both dated Jul 30, 2025 and not visibly altered in substance) could be treated as reliably representing the report's original framing.
- **Exact page/section numbers for the "80 curated coding tasks" methodology (CWE selection, 5 tasks per language-CWE combination, etc.):** Confirmed only at the level of the press release's prose description ("Veracode designed a set of 80 code completion tasks... according to the MITRE Common Weakness Enumeration (CWE) system"). Finer methodological detail (e.g., "5 task instances per language-CWE combination" across 4 CWEs — SQL Injection CWE-89, Cross-Site Scripting CWE-80, Log Injection CWE-117, Insecure Cryptographic Algorithms CWE-327) appeared consistently in secondary summaries and in Veracode's own later 2026-report methodology language, but was not found verbatim in the 2025 press release, blog, or landing page text that was accessible — so it is not included above as a sourced quote for the 2025 report specifically.
